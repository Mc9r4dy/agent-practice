# 数据库安全运维教学智能体——开发环境使用说明

## 1. 适用范围

本文说明如何在 Visual Studio Code 中启动、进入、测试、重置和停止“数据库安全运维教学智能体”的开发环境。当前环境阶段只包含开发工作区和 MySQL 8.4 教学沙箱，尚未包含前端、后端业务接口、大模型接入、故事状态机和评分模块。

总仓库：`F:\project_shuqi` → `/workspace`

当前智能体：`F:\project_shuqi\01_db-security-ops-teaching-agent` → `/workspace/01_db-security-ops-teaching-agent`

本地打开目录固定为当前智能体目录：

```text
F:\project_shuqi\01_db-security-ops-teaching-agent
```

## 2. 安全边界

- Windows 服务 `MySQL57` 使用 3306，禁止连接、停止、修改或导入本项目数据。
- 现有 MySQL57 数据目录 `E:\MySql` 不属于本项目，禁止读写。
- 教学沙箱使用独立的 MySQL 8.4 容器，只绑定 `127.0.0.1:3307`，不向局域网公开。
- 全部教学数据均为带明显标记的合成数据；所谓攻击痕迹只是不可执行的日志摘要。
- `.env` 包含本地随机密码，已被 `.gitignore` 排除；禁止把其内容写入开发日志、截图、提交或聊天消息。
- `QuickReset` 只重放合成种子数据，不删除数据卷。
- `Rebuild` 会删除并重建本项目固定数据卷 `shuqi-db-agent-mysql-data`，但脚本会先校验项目根目录、容器名和卷名。
- 禁止执行 `docker system prune`、`docker volume prune` 等全局清理命令。
- 开发容器不挂载 Docker 管理套接字，不能借开发容器任意控制宿主机 Docker。
- 本次根仓库集成不运行 QuickReset、Rebuild、`down --volumes`、prune 或任何数据卷清理。

## 3. 前置条件

1. Docker Desktop 已安装并完全进入 Running 状态；
2. Docker Compose v2 可用；
3. Visual Studio Code 已安装；
4. 建议安装工作区推荐扩展，尤其是 Dev Containers；
5. 本地打开的目录必须是上述当前智能体目录。

本机 Windows PowerShell 采用默认 Restricted 执行策略。不要直接运行 `& .\scripts\sandbox.ps1`，也不要为本项目永久修改系统执行策略。本文和 VS Code 任务均通过只对单次新进程生效的 `-ExecutionPolicy Bypass` 调用脚本。

## 4. 首次启动

### 4.1 推荐：通过 VS Code 任务

1. 在 VS Code 中以本地 Windows 窗口打开项目根目录；
2. 选择 `Terminal > Run Task`；
3. 运行 `Sandbox: Preflight`；
4. 预检通过后运行 `Sandbox: Start`；
5. 等待输出显示 `shuqi-mysql-sandbox` 为 healthy、`shuqi-workspace` 为 running。

首次 Start 会自动创建本地 `.env`，其中 3 个密码分别随机生成。脚本不会输出密码值。

### 4.2 等价命令行方式

在项目根目录的 Windows PowerShell 中运行：

```powershell
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File .\scripts\sandbox.ps1 -Action Preflight
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File .\scripts\sandbox.ps1 -Action Start
```

正常结果应满足：

- `shuqi-mysql-sandbox`：healthy；
- `shuqi-workspace`：running；
- 主机端口映射：`127.0.0.1:3307->3306/tcp`；
- Windows `MySQL57` 仍为 Running，主机 3306 仍由原服务监听。

## 5. 进入 Dev Container

1. 必须先在本地 Windows 窗口完成 Start，确保 `.env` 和两个容器已经就绪；
2. 在本地先打开 `01_db-security-ops-teaching-agent` 子目录；
3. 打开 VS Code 命令面板，选择 `Dev Containers: Reopen in Container`；
4. VS Code 将连接 `shuqi-workspace`，工作目录为 `/workspace/01_db-security-ops-teaching-agent`；
5. 容器内应提供 Python 3.13、Node.js 24、Git、MySQL 客户端和 pytest。

进入 Dev Container 后，可在容器终端直接运行：

```bash
pwd
git rev-parse --show-toplevel
git status -sb
git config --show-origin --get-all safe.directory
pytest -q
```

预期 `pwd` 为 `/workspace/01_db-security-ops-teaching-agent`，Git 根目录为 `/workspace`，有效 `safe.directory` 只包含精确 `/workspace`。`git.openRepositoryInParentFolders=always` 让 VS Code 发现父级总仓库。

`.vscode/tasks.json` 中的 `Sandbox: ...` 生命周期任务依赖 Windows `powershell.exe`，应在本地 Windows 窗口运行。远程容器窗口中不挂载 Docker 管理套接字；需要启动、停止、查看 Compose 日志或重建时，请在本地项目窗口或单独的 Windows PowerShell 中执行对应任务/命令。

`Sandbox: Preflight/Start/Status/Logs/Test/QuickReset/Rebuild/Stop` 全部是 Windows 主机任务，不在 Linux Dev Container 内运行。`QuickReset` 会删除九张教学表的现有教学场景数据后重放合成种子；`Rebuild` 会执行 `down --volumes` 删除教学数据卷，本次根仓库集成实施和回滚禁止使用。

若 `git config --show-origin --get-all safe.directory` 出现 `*`、`/workspace/*` 或额外路径，停止验收。不要自动修改宿主 Git 配置；只清理容器内复制的全局 `safe.directory` 冲突项，然后重新检查。

Dev Containers 可能复制宿主 `.gitconfig`，并通过会话级 credential helper 或 SSH agent 提供凭据桥接；这不等于把令牌写入镜像。不得在镜像、项目文件或日志中记录 PAT、私钥、密码或 credential helper 的完整值。只读远端可用 `git ls-remote origin refs/heads/main` 验证；若用户不授权凭据使用，记录为“未启用”，不误判为本地仓库识别失败。

当前 `/workspace` 挂载整个总仓库，因此 01 容器可以读写四个智能体的文件，四个智能体按同一开发信任域管理。真实生产凭据不得放入仓库目录；未来运行不可信代码或多人隔离开发时必须重新评审独立仓库、worktree 或外部秘密挂载。

## 6. 日常操作

### 6.1 VS Code 任务

本地 Windows 窗口的 `Terminal > Run Task` 提供：

| 任务 | 作用 | 是否改变数据 |
| --- | --- | --- |
| `Sandbox: Preflight` | 检查 Docker、3307 和 MySQL57 基线 | 否，也不创建 `.env` |
| `Sandbox: Start` | 解析配置、构建并启动环境 | 首次启动会初始化合成数据 |
| `Sandbox: Status` | 显示项目容器状态 | 否 |
| `Sandbox: Logs` | 显示项目最近 200 行日志 | 否 |
| `Sandbox: Test` | 在 workspace 内运行全部 pytest | 集成测试会临时修改并恢复教学状态 |
| `Sandbox: QuickReset` | 重放标准合成种子数据 | 是，只重置教学数据 |
| `Sandbox: Rebuild` | 删除本项目数据卷后完整重建 | 是，删除全部教学沙箱数据 |
| `Sandbox: Stop` | 停止并删除本项目容器 | 否，保留数据卷 |

### 6.2 等价命令

把 `<ACTION>` 替换为 `Status`、`Logs`、`Test`、`QuickReset`、`Rebuild` 或 `Stop`：

```powershell
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File .\scripts\sandbox.ps1 -Action <ACTION>
```

常规开发结束时运行 Stop；下次 Start 会复用教学数据卷。

## 9. 重置与回滚

### 9.1 快速重置

适合恢复标准课堂数据，通常几秒完成：

```powershell
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File .\scripts\sandbox.ps1 -Action QuickReset
```

### 9.2 完整重建

仅当初始化结构、账号脚本或数据库运行参数发生变化，或快速重置无法恢复时使用：

```powershell
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File .\scripts\sandbox.ps1 -Action Rebuild
```

Rebuild 只允许操作固定 Compose 项目、固定容器和固定数据卷。若安全校验失败，应停止排查，不能绕过检查执行人工模糊删除。

### 9.3 普通停止

```powershell
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File .\scripts\sandbox.ps1 -Action Stop
```

Stop 保留 `shuqi-db-agent-mysql-data`，不影响 MySQL57。

## 10. 常见故障

### Docker 未就绪

启动 Docker Desktop，等界面和 `docker info` 都显示可用后重新运行 Preflight。不要在未确认的情况下强制结束 Docker 进程。

### 3307 被占用

脚本会拒绝启动，不会结束占用进程，也不会自动回退到 3306。人工识别占用者；只有确认它属于本项目时才能处理。

### 直接运行 `.ps1` 被执行策略阻止

这是当前主机的预期行为。使用本文完整的 `powershell.exe ... -ExecutionPolicy Bypass -File` 命令，或使用本地 VS Code 的 `Sandbox: ...` 任务；不要永久修改执行策略。

### MySQL 容器不健康

先运行 `Sandbox: Logs`。若错误来自初始化脚本或数据库参数，修复后运行 Rebuild。不要尝试连接 MySQL57 作为替代。

### 依赖镜像拉取失败

当前环境已准备固定标签镜像。若以后需要重新获取，应先检查网络和镜像源，不要随意修改全局 Docker 配置；记录镜像来源和摘要。

### 测试缓存权限警告

统一使用 `Sandbox: Test` 或容器内 `pytest -q`。若项目根目录出现由 root 创建的 `.pytest_cache`，只清理项目根目录中精确解析后的该缓存目录，不做递归通配或全局清理。

### 权限测试失败

停止验收，检查账号初始化脚本、对象授权和数据卷是否为旧版本。不能给教学账号 `ALL PRIVILEGES`，不能放宽到 MySQL 系统库。

## 12. 终审修复补充（2026-07-21）

### 12.1 VS Code 关闭、切换与断连

当前 `shutdownAction=none`：**关闭或切换 VS Code 不自动停止 Compose**。Compose 生命周期由 Windows 主机任务显式管理；只有开发者明确结束本项目环境时才运行 `Sandbox: Stop`。不再让旧 VS Code 会话的延迟 cleanup 停掉新会话正在使用的 workspace 和 MySQL 沙箱。

遇到断连时：

1. 先在 Windows 窗口运行 `Sandbox: Status`；如容器未运行，再运行 `Sandbox: Start`。这两步统称 `Sandbox: Status/Start`。
2. 确认 workspace 与 MySQL 状态正常后，再使用 `Reload Window/Reopen in Container` 恢复 VS Code 会话。
3. **不要 Rebuild/QuickReset**。它们是数据或环境恢复操作，不是编辑器断连恢复手段。

该修复基于已复现的 Dev Containers 日志与静态配置契约；不表示本轮自动化曾模拟或验证 VS Code GUI 关闭行为。

### 12.2 环境阶段完整回滚

DEV-035 中的 Task 3 回滚是当时任务失败的历史流程，只定位并回退 Task 2/Task 1；保留该历史记录，不用它代替当前 HEAD 的完整环境阶段回滚。

以下是仅在用户明确决定回滚时才手工执行的 fail-closed 流程。本章的普通反向提交要把 05/06/07、Dev Container 配置、环境测试与计划复选框作为同一阶段回退，同时保留截止回滚开始时的完整开发日志。从总仓库根目录 `F:\project_shuqi` 运行：

```powershell
$ErrorActionPreference = 'Stop'
$base = '25351d020a9ef413d9288010028acba579fe7938'
$marker = '^Close final Dev Container review gaps$'
$logPath = '01_db-security-ops-teaching-agent/04_开发日志.md'

$branch = git branch --show-current
if ($LASTEXITCODE -ne 0 -or $branch -cne 'main') { throw 'Rollback requires the exact main branch' }
if (@(git status --porcelain).Count -ne 0) { throw 'Rollback requires a clean worktree' }
$preRollbackHead = git rev-parse HEAD
if ($LASTEXITCODE -ne 0 -or [string]::IsNullOrWhiteSpace($preRollbackHead)) { throw 'Cannot resolve pre-rollback HEAD' }
$remoteLines = @(git ls-remote origin refs/heads/main)
if ($LASTEXITCODE -ne 0 -or $remoteLines.Count -ne 1) { throw 'Remote main must resolve exactly once before rollback' }
$remoteHead = ($remoteLines[0] -split '\s+')[0]
if ([string]::IsNullOrWhiteSpace($remoteHead) -or $remoteHead -ne $preRollbackHead) { throw 'Remote main must exactly match pre-rollback HEAD' }

$markerMatches = @(git log --format='%H%x09%s' --grep=$marker)
if ($LASTEXITCODE -ne 0 -or $markerMatches.Count -ne 1) { throw 'Rollback marker must resolve to exactly one commit' }
$rollbackHead = ($markerMatches[0] -split "`t", 2)[0]
if ([string]::IsNullOrWhiteSpace($rollbackHead)) { throw 'Rollback marker SHA is empty' }

git merge-base --is-ancestor $base $rollbackHead
if ($LASTEXITCODE -ne 0) { throw 'Fixed baseline is not an ancestor of rollback head' }
git merge-base --is-ancestor $rollbackHead $preRollbackHead
if ($LASTEXITCODE -ne 0) { throw 'Rollback head is not on current HEAD history' }
$mergeCommits = @(git rev-list --merges "$base..$preRollbackHead")
if ($LASTEXITCODE -ne 0 -or $mergeCommits.Count -ne 0) { throw 'Rollback range must be linear and contain no merge commits' }

$mysqlBefore = docker inspect shuqi-mysql-sandbox | ConvertFrom-Json
if ($LASTEXITCODE -ne 0 -or $mysqlBefore.State.Health.Status -ne 'healthy') { throw 'Healthy MySQL baseline required' }
$mysqlIdBefore = $mysqlBefore.Id
$mysqlDataMountBefore = @($mysqlBefore.Mounts | Where-Object Destination -eq '/var/lib/mysql')
if ($mysqlDataMountBefore.Count -ne 1 -or $mysqlDataMountBefore[0].Name -ne 'shuqi-db-agent-mysql-data') { throw 'Teaching volume baseline mismatch' }
docker volume inspect shuqi-db-agent-mysql-data | Out-Null
if ($LASTEXITCODE -ne 0) { throw 'Teaching volume baseline missing' }
$mysql57Before = Get-Service MySQL57
if ($mysql57Before.Status -ne 'Running') { throw 'MySQL57 must be running before rollback' }
$mysql57PidBefore = (Get-CimInstance Win32_Service -Filter "Name='MySQL57'").ProcessId
if ($mysql57PidBefore -le 0) { throw 'MySQL57 PID baseline failed' }
$port3306ConnectionsBefore = @(Get-NetTCPConnection -State Listen -LocalPort 3306)
$foreign3306Before = @($port3306ConnectionsBefore | Where-Object { $_.OwningProcess -ne $mysql57PidBefore })
if ($port3306ConnectionsBefore.Count -eq 0 -or $foreign3306Before.Count -ne 0) { throw 'Port 3306 ownership baseline mismatch' }
$port3306Before = @(($port3306ConnectionsBefore) | ForEach-Object { "$($_.LocalAddress)|$($_.LocalPort)|$($_.OwningProcess)" } | Sort-Object)
$port3307Before = @((Get-NetTCPConnection -State Listen -LocalPort 3307) | ForEach-Object { "$($_.LocalAddress)|$($_.LocalPort)|$($_.OwningProcess)" } | Sort-Object)
if ($port3307Before.Count -ne 1 -or -not $port3307Before[0].StartsWith('127.0.0.1|3307|')) { throw 'Port 3307 baseline mismatch' }

$commits = @(git rev-list "$base..$rollbackHead")
if ($LASTEXITCODE -ne 0 -or $commits.Count -eq 0) { throw 'Rollback commit list is empty or unreadable' }
git revert --no-commit $commits
if ($LASTEXITCODE -ne 0) {
    git revert --abort
    throw 'Revert failed; abort completed, stop and diagnose'
}

git restore --source=$preRollbackHead --staged --worktree -- 01_db-security-ops-teaching-agent/04_开发日志.md
if ($LASTEXITCODE -ne 0) { throw 'Failed to preserve complete development log' }
$confirmation = Read-Host "Use an editor to append the actual rollback record to $logPath, then type ROLLBACK-LOG-APPENDED"
if ($confirmation -cne 'ROLLBACK-LOG-APPENDED') { throw 'Rollback stopped before log confirmation' }
git add -- $logPath
if ($LASTEXITCODE -ne 0) { throw 'Failed to stage appended rollback log' }
git diff --cached --quiet -- $logPath
if ($LASTEXITCODE -eq 0) { throw 'No appended rollback log detected' }
if ($LASTEXITCODE -ne 1) { throw 'Cannot validate appended rollback log' }

docker compose --project-name shuqi-db-agent --env-file 01_db-security-ops-teaching-agent/.env -f 01_db-security-ops-teaching-agent/infra/compose.yaml config --quiet
if ($LASTEXITCODE -ne 0) { throw 'Rolled-back Compose configuration is invalid' }
docker compose --project-name shuqi-db-agent --env-file 01_db-security-ops-teaching-agent/.env -f 01_db-security-ops-teaching-agent/infra/compose.yaml up -d --build --no-deps --force-recreate workspace
if ($LASTEXITCODE -ne 0) { throw 'Workspace-only rollback recreation failed' }
docker exec -u vscode shuqi-workspace pytest -q
if ($LASTEXITCODE -ne 0) { throw 'Post-rollback pytest failed' }

$mysqlAfter = docker inspect shuqi-mysql-sandbox | ConvertFrom-Json
if ($LASTEXITCODE -ne 0 -or $mysqlAfter.Id -ne $mysqlIdBefore -or $mysqlAfter.State.Health.Status -ne 'healthy') { throw 'MySQL identity or health changed' }
$mysqlDataMountAfter = @($mysqlAfter.Mounts | Where-Object Destination -eq '/var/lib/mysql')
if ($mysqlDataMountAfter.Count -ne 1 -or $mysqlDataMountAfter[0].Name -ne $mysqlDataMountBefore[0].Name) { throw 'Teaching volume changed' }
docker volume inspect shuqi-db-agent-mysql-data | Out-Null
if ($LASTEXITCODE -ne 0) { throw 'Teaching volume missing after rollback' }
$mysql57After = Get-Service MySQL57
$mysql57PidAfter = (Get-CimInstance Win32_Service -Filter "Name='MySQL57'").ProcessId
if ($mysql57After.Status -ne 'Running' -or $mysql57PidAfter -ne $mysql57PidBefore) { throw 'MySQL57 changed during rollback' }
$port3306After = @((Get-NetTCPConnection -State Listen -LocalPort 3306) | ForEach-Object { "$($_.LocalAddress)|$($_.LocalPort)|$($_.OwningProcess)" } | Sort-Object)
$port3307After = @((Get-NetTCPConnection -State Listen -LocalPort 3307) | ForEach-Object { "$($_.LocalAddress)|$($_.LocalPort)|$($_.OwningProcess)" } | Sort-Object)
if (Compare-Object $port3306Before $port3306After) { throw 'Port 3306 listener changed' }
if (Compare-Object $port3307Before $port3307After) { throw 'Port 3307 listener changed' }

git commit -m 'Rollback complete environment stage'
if ($LASTEXITCODE -ne 0) { throw 'Rollback commit failed' }
git push origin main
if ($LASTEXITCODE -ne 0) { throw 'Rollback push failed' }
$local = git rev-parse HEAD
$remoteLines = @(git ls-remote origin refs/heads/main)
if ($LASTEXITCODE -ne 0 -or $remoteLines.Count -ne 1) { throw 'Remote main lookup failed' }
$remote = ($remoteLines[0] -split '\s+')[0]
if ([string]::IsNullOrWhiteSpace($local) -or $local -ne $remote) { throw 'Local and remote SHA differ' }
```

任何前置检查失败都立即停止；`git revert --no-commit` 失败时只执行 `git revert --abort` 然后停止。流程只定向重建 workspace，禁止 `git reset --hard`、force push、Rebuild、QuickReset、`down --volumes`、`docker system prune` 和 `docker volume prune`。
