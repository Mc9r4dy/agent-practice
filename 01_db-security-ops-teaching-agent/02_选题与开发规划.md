## 1. 选题背景

指导手册将“数据库安全运维智能体”列为网络安全专业课情景教学智能体，支撑课程为“数据库原理与安全”，核心教学定位包括 SQL 运维、权限管控、SQL 注入攻防、数据库备份恢复和安全基线检查。

传统数据库安全课程常将知识讲解、命令练习和事件处置分开进行，学员难以形成完整的安全运维思路。本项目拟引入大语言模型、规则检测和隔离的 MySQL 教学数据库，以真实企事业单位事件为背景，引导学员完成巡检、研判、处置、恢复和报告编写，形成“知识学习—情景决策—安全实操—结果反馈”的教学闭环。

## 2. 项目定位

本项目定位为**数据库安全运维情景化教学助手**，主要用户是正在学习数据库原理、MySQL 运维和网络安全基础的学生。系统不直接管理真实生产数据库，不追求替代专业数据库管理平台，而是通过可重置的教学沙箱、安全规则和大模型讲解，帮助学员掌握标准化的数据库安全运维流程。

项目采用混合式教学沙箱路线：

- 巡检查询、账号查看、权限分析和备份验证可在本地 MySQL 教学环境中真实执行；
- 高风险修改、攻击行为和破坏性恢复使用模拟数据、固定任务或白名单操作；
- 大语言模型负责场景引导、知识解释和提示生成，不直接持有数据库高权限凭据，也不能任意执行 SQL；
- 规则引擎负责客观检测与评分，避免完全依赖大模型判断。

## 3. 建设目标

### 3.1 总体目标

开发一个能够引导学员在企业数据库安全事件中完成 MySQL 安全巡检、权限审计、异常 SQL 研判、备份恢复验证和处置报告生成的教学智能体。

### 3.2 教学目标

1. 掌握 MySQL 安全基线巡检的常用命令、检查项和判断标准；
2. 理解最小权限原则，能够识别异常账号、过度授权和危险访问来源；
3. 能够从模拟审计日志中识别批量查询、异常登录和疑似 SQL 注入行为；
4. 掌握数据库备份有效性检查和隔离恢复验证流程；
5. 能够按照发现、研判、处置、恢复、复盘的步骤形成安全运维闭环；
6. 能够生成结构清晰、证据充分的数据库安全运维报告。

### 3.3 项目成果目标

1. 可运行的 Web 教学系统；
2. 可重置的 MySQL 教学沙箱和模拟业务数据；
3. 数据库安全知识库与大语言模型问答能力；
4. 三条可选择、最终汇合的故事任务分支；
5. 安全基线、权限、日志和备份四类实操任务；
6. 风险评分、学习评分及报告导出功能；
7. 仅作用于教学沙箱、能够一键重置的受控攻击回放能力；
8. 与指导手册要求对应的功能手册、源代码及数据库压缩包、安全审计报告。

## 4. 用户与使用场景

### 4.1 主要用户

- **学员：**选择任务、执行查询、分析风险、完成处置并查看评分；
- **教师或助教：**查看任务完成情况、评分和报告，必要时重置教学场景；
- **系统管理员：**维护场景数据、知识库、检测规则和大模型配置。

### 4.2 核心故事背景

某市公共服务平台的 MySQL 业务数据库出现异常高权限账号和大量可疑查询，同时夜间备份任务执行失败。平台存储用户身份信息和业务办理记录，存在数据泄露及服务中断风险。单位要求数据库安全运维岗（学员扮演）在 2 小时内完成风险排查、权限处置、备份恢复验证和安全加固。

### 4.3 可扮演角色

- 数据库安全运维工程师；
- 数据库管理员；
- 应急响应工程师。

## 5. 故事线与任务分支

### 5.1 决策分支一：安全基线巡检

学员选择先进行 MySQL 安全基线检查，查看版本、账号、远程访问、密码策略、日志配置和备份配置。系统根据执行过程提示风险，完成后解锁“账号权限审计”。

预设发现包括：

- 存在可从任意来源连接的高权限账号；
- 业务账号拥有超出职责范围的权限；
- 审计或关键日志配置不足；
- 备份任务状态异常。

### 5.2 决策分支二：账号权限审计

学员选择先分析账号与权限，识别新增可疑账号、过度授权、共享账号及异常来源。完成后解锁“日志与可疑 SQL 分析”。

预设发现包括：

- 新增账号来源不明；
- 普通应用账号拥有管理权限；
- 账号主机范围设置过宽；
- 长期未使用账号仍处于启用状态。

### 5.3 决策分支三：异常日志分析

学员选择先分析模拟的数据库日志和 Web 访问日志，识别批量查询、异常时间访问、失败登录和疑似 SQL 注入请求。完成后解锁“备份恢复验证”。

预设发现包括：

- 同一来源短时间出现大量失败查询；
- 非工作时段出现批量读取行为；
- Web 请求参数与数据库异常语句在时间上相关；
- 可疑账号访问了敏感业务表。

### 5.4 汇合任务：风险处置与闭环

所有分支最终进入统一闭环任务：

1. 禁用异常账号；
2. 撤销不合理权限；
3. 调整高风险访问来源；
4. 验证备份文件及校验信息；
5. 在隔离恢复库中完成恢复验证；
6. 汇总风险证据、操作过程和改进建议；
7. 生成数据库安全运维报告。

### 5.5 失败分支

发生以下情况时进入失败分支：

- 超过任务时限仍未完成关键处置；
- 将正常账号误判并直接删除；
- 在非隔离环境尝试执行高风险 SQL；
- 未验证备份便直接覆盖数据库；
- 未处理高危权限或异常来源便提交报告。

系统展示相应风险后果，并通过分级提示引导学员重新完成任务。

### 5.6 模拟攻击方案（仅限教学沙箱）

本项目使用“受控攻击回放”构造教学事件。攻击过程由固定场景和预设事件驱动，只作用于隔离的 MySQL 教学沙箱和合成数据，不提供对外攻击入口，也不允许学员或大语言模型提交任意攻击载荷。

#### 5.6.1 模拟攻击链

1. **入口阶段—SQL 注入迹象：**回放预设异常 Web 请求和数据库日志，模拟业务系统参数化查询缺失后产生的 SQL 注入迹象。
2. **权限利用阶段：**模拟应用账号权限配置过大，使其能够访问超出业务职责范围的数据表，并生成异常授权证据。
3. **异常访问阶段：**对合成用户数据执行受限的批量查询回放，产生非工作时段访问、查询量突增和敏感表读取记录。
4. **持久化阶段：**在场景初始化时预置来源异常的高权限账号，供学员识别、研判、锁定和回收权限。
5. **备份干扰阶段：**模拟备份任务失败、校验值不一致或最新备份不可用，不实际删除备份文件和业务数据。
6. **证据生成阶段：**形成 Web 访问日志、MySQL 日志、账号权限快照、备份记录和场景事件时间线。

#### 5.6.2 学员处置任务

- 定位异常请求和可疑 SQL；
- 识别被滥用的应用账号和异常高权限账号；
- 撤销过度授权并锁定可疑账号；
- 验证备份文件，在隔离恢复库中完成恢复验证；
- 完成安全加固、证据整理和事件报告。

#### 5.6.3 攻击回放安全边界

- 仅使用合成或脱敏数据；
- 沙箱禁止访问外网和宿主机其他数据库；
- 攻击事件只能通过固定场景编号触发，不接受任意攻击参数；
- 大语言模型不能直接执行 SQL，只能调用后端受控工具；
- 限制查询数量、执行时间和资源占用；
- 拦截删除库表、无条件批量修改等破坏性操作；
- 每次演练结束后可一键恢复标准快照。

## 6. 功能需求

### 6.1 故事线引导模块

- 展示事件背景、角色对话和倒计时；
- 支持三条起始决策路径；
- 根据任务结果解锁后续节点；
- 记录选择顺序、用时、错误和提示次数；
- 支持失败后重试和场景重置。

### 6.2 大语言模型教学助手

- 解读任务要求和数据库安全概念；
- 根据当前节点提供分级提示，而不是直接给出完整答案；
- 解释 SQL 查询结果、风险成因和修复原则；
- 基于知识库回答 MySQL 安全运维问题；
- 在生成回答时标注知识来源或对应检查项；
- 当模型不可用时，退化为预设知识提示，不阻塞主任务。

### 6.3 MySQL 教学沙箱

- 提供模拟公共服务平台业务库和脱敏合成数据；
- 预置正常账号、异常账号、过度授权及审计线索；
- 提供只读学员账号和受控处置接口；
- 支持一键初始化和场景重置；
- 高风险操作在隔离副本中执行；
- 不使用真实个人信息或生产凭据。

### 6.4 安全基线巡检模块

- 检查数据库版本与基础配置；
- 检查远程访问和账号主机范围；
- 检查高权限、匿名、长期未用账号；
- 检查密码策略和关键日志配置；
- 检查备份任务状态及最近备份时间；
- 输出检查结果、风险等级和修复建议。

### 6.5 权限审计模块

- 展示账号、来源与授权关系；
- 对照最小权限规则识别过度授权；
- 检测高权限账号、共享账号和异常账号；
- 支持撤销权限、锁定账号等白名单处置；
- 在处置前展示影响范围和确认提示。

### 6.6 SQL 与日志分析模块

- 加载预设的 MySQL 日志和 Web 访问日志；
- 支持按时间、账号、来源和语句类型筛选；
- 将 Web 请求与数据库语句进行时间关联；
- 标记批量查询、异常登录、敏感表访问和疑似注入模式；
- 展示证据链、风险说明和建议处置。

### 6.7 备份恢复演练模块

- 展示备份时间、大小、状态和校验信息；
- 判断备份是否完整、是否满足恢复条件；
- 在隔离恢复库中执行恢复验证；
- 比较恢复前后的表结构、记录数量和关键校验值；
- 记录恢复步骤、耗时和异常信息。

### 6.8 评分与报告模块

- 按任务完成度、风险识别率、操作规范性、用时和提示次数评分；
- 区分知识错误、流程错误和危险操作；
- 生成事件概述、检查结果、证据、处置、恢复验证和改进建议；
- 支持查看和导出数据库安全运维报告；
- 报告不得包含明文密码、完整令牌或真实敏感数据。

### 6.9 教师管理模块（基础版）

- 查看学员任务记录和最终得分；
- 查看学员选择的故事路径；
- 重置场景；
- 维护知识条目、规则说明和标准答案；
- 不在第一阶段建设复杂班级、组织和多租户功能。

### 6.10 受控攻击回放模块

- 根据固定场景编号加载预设异常状态、日志和证据；
- 支持开始、暂停、结束和一键重置回放；
- 记录每个攻击事件的发生时间、目标对象和预期证据；
- 保证 Web 日志、MySQL 日志、账号权限快照和备份记录在时间线上相互对应；
- 不接收任意 SQL、命令、地址或外部目标参数；
- 回放异常时自动终止并恢复教学沙箱标准快照。

## 7. 非功能需求

### 7.1 安全性

- 大语言模型服务不得直接获得 MySQL 管理员密码；
- 学员默认使用只读账号，处置操作必须通过后端固定接口；
- SQL 执行前进行语句类型、目标对象和权限校验；
- 拦截 DROP、TRUNCATE、无条件 DELETE/UPDATE 等危险操作；
- 所有操作保留审计记录；
- 使用合成数据，避免真实个人信息进入模型或日志；
- API 密钥、数据库密码通过环境变量或本地密钥配置保存，不写入代码仓库。

### 7.2 可用性

- 主流程在大语言模型暂时不可用时仍可完成；
- 数据库连接失败时给出明确原因和恢复入口；
- 场景可一键重置，避免前一次操作影响下一次演示；
- 关键任务状态自动保存，页面刷新后可恢复进度。

### 7.3 性能

- 常规页面和规则巡检应在可接受等待时间内返回；
- 大模型回答采用超时控制，并显示生成状态；
- 日志数据使用教学规模，保证普通个人电脑能够运行演示。

### 7.4 可维护性

- 场景、知识库、检测规则、评分规则相互独立；
- 大模型供应方通过统一适配接口配置，便于替换；
- 关键模块具备日志、错误码和基础自动化测试；
- 项目提供环境配置示例、启动说明和重置说明。

## 8. 总体技术方案

### 8.1 推荐技术路线

- **开发工具：**Visual Studio Code；
- **前端：**Vue 3 与常用组件库，用于故事界面、任务面板、巡检结果和报告展示；
- **后端：**Python + FastAPI，提供任务、场景、规则、数据库和大模型接口；
- **教学数据库：**MySQL，存放模拟业务数据和安全场景数据；
- **应用数据：**第一版使用 SQLite 保存用户、任务进度、评分和报告；教学业务数据继续存放在 MySQL 沙箱中；
- **大模型：**通过可配置的兼容接口接入，不将具体模型写死在业务代码中；
- **知识检索：**第一阶段使用整理后的 Markdown 知识条目和关键词检索，第二阶段再增加向量检索；
- **部署方式：**第一版采用本地部署，并提供 Docker Compose 配置统一启动前端、后端和 MySQL 教学沙箱；开发阶段也可在 Visual Studio Code 中分别启动各服务。

### 8.2 架构分层

1. **表现层：**登录、故事线、任务面板、SQL 操作区、智能问答、评分和报告页面；
2. **接口层：**用户、场景、任务、巡检、权限、日志、备份、问答和报告 API；
3. **业务层：**故事状态机、评分引擎、规则引擎、提示策略和报告生成器；
4. **AI 层：**模型适配器、提示词模板、知识检索、回答安全过滤；
5. **数据层：**应用数据库、知识库、操作审计日志和报告文件；
6. **沙箱层：**MySQL 教学库、预设漏洞与异常、备份文件和隔离恢复库。

### 8.3 核心数据流

1. 学员选择角色和起始决策；
2. 故事状态机下发当前任务和可用操作；
3. 学员通过固定接口执行查询或白名单处置；
4. 后端连接教学沙箱，返回脱敏后的执行结果；
5. 规则引擎判定风险、完成度和得分；
6. 大模型结合任务状态、规则结果和知识条目生成解释或分级提示；
7. 系统记录证据和操作日志，更新故事节点；
8. 所有关键任务完成后生成安全运维报告。

## 9. 模块边界

| 模块 | 主要职责 | 依赖 |
| --- | --- | --- |
| 场景引擎 | 管理角色、节点、分支、解锁和失败状态 | 场景配置、任务记录 |
| 攻击回放服务 | 按固定场景注入异常状态、日志和证据，并负责安全重置 | 攻击事件配置、沙箱管理 |
| 规则引擎 | 执行基线、权限、日志和备份检查 | MySQL 沙箱、规则配置 |
| SQL 安全网关 | 校验和执行只读或白名单 SQL | 权限策略、MySQL 沙箱 |
| AI 教学服务 | 问答、解释、分级提示和文字总结 | 模型接口、知识检索 |
| 评分服务 | 计算过程分和结果分 | 任务记录、规则结果 |
| 报告服务 | 汇总证据、处置和建议 | 评分、审计日志、模板 |
| 沙箱管理 | 初始化、重置、备份和隔离恢复 | MySQL、场景脚本 |

## 10. 数据设计概览

建议的核心数据对象包括：

- 用户与角色；
- 场景、节点和分支；
- 攻击场景、攻击事件和证据时间线；
- 教学任务与完成记录；
- 检查规则与检查结果；
- 学员操作与审计日志；
- 模拟数据库账号与授权快照；
- 日志样本与风险标签；
- 备份记录与恢复验证结果；
- 知识条目与来源；
- 评分明细与最终报告。

正式数据库表结构在详细实施计划阶段确定。

## 11. 异常处理与降级策略

- **大模型超时或不可用：**显示预设提示和知识条目，允许继续完成任务；
- **模型回答缺少依据：**提示“未找到可靠知识依据”，不将回答计入任务结论；
- **MySQL 连接失败：**暂停实操、保留进度并提供重新连接或重置入口；
- **危险 SQL：**拒绝执行，记录一次危险操作并给出原理说明；
- **攻击回放异常：**立即停止事件注入，标记失败节点并将沙箱恢复至标准快照；
- **恢复验证失败：**保留失败原因，允许重新选择备份或重置恢复库；
- **场景数据被破坏：**通过初始化脚本恢复到标准快照；
- **报告生成失败：**保留结构化任务结果，可重新生成报告。

## 12. 测试计划

### 12.1 单元测试

- 场景节点解锁与失败状态；
- 攻击事件顺序、证据生成和重置状态；
- 风险规则判断；
- SQL 白名单和危险语句拦截；
- 评分计算；
- 报告字段生成。

### 12.2 集成测试

- 后端与 MySQL 教学沙箱连接；
- 攻击回放服务与场景引擎、规则引擎和沙箱的协作；
- 巡检、权限、日志、备份模块的数据流；
- 大模型适配器和知识检索；
- 场景重置与恢复库初始化。

### 12.3 场景验收测试

- 三条起始分支均可独立进入并最终汇合；
- 固定攻击场景能够完整回放，且各类证据在同一时间线上一致；
- 正确操作能够解锁后续任务；
- 错误或危险操作能够触发提示、扣分或失败分支；
- 大模型不可用时仍能完成完整教学流程；
- 最终报告能够反映学员实际选择和操作证据。

### 12.4 安全测试

- 验证模型不能绕过后端直接操作数据库；
- 验证攻击回放不能访问外网、宿主机其他数据库或非预设目标；
- 验证攻击回放接口拒绝任意 SQL、命令和地址参数；
- 验证高风险 SQL 被拦截；
- 验证 API 密钥和数据库密码不出现在日志、页面和报告中；
- 验证普通学员无法访问教师或系统管理接口；
- 验证导出报告中的敏感字段已脱敏。

## 14. 验收标准

1. 能够启动并重置完整的教学场景；
2. 三条起始决策分支均可正常完成并汇合；
3. 至少覆盖账号、权限、日志、备份和基础配置等核心巡检项；
4. 能够识别预设的异常账号、过度授权、异常 SQL 和无效备份；
5. 能够按固定场景完整回放模拟攻击，并生成一致的日志、权限、备份和事件时间线证据；
6. 攻击回放不能访问外网、宿主机其他数据库或接受任意攻击参数；
7. 学员只能执行只读查询和受控处置，高风险 SQL 会被拦截；
8. 大语言模型能结合任务和知识库提供解释及分级提示；
9. 大模型不可用时主教学流程仍可继续；
10. 能够记录学员过程、计算得分并生成安全运维报告；
11. 场景数据均为合成或脱敏数据，不包含真实个人信息；
12. 提供清晰的启动、配置、回放、重置、演示和测试说明。

## 15. 本期范围之外

为保证项目能够按期落地，第一版不包含：

- 直接接入真实生产数据库；
- 自动执行任意大模型生成的 SQL；
- 真实攻击工具或破坏性攻击能力；
- 复杂的多租户、学校组织和班级管理；
- 移动端客户端；
- 多种数据库同时适配；
- 全自动数据库运维平台或商业级监控能力。

## 16. 风险与应对

| 风险 | 影响 | 应对措施 |
| --- | --- | --- |
| 大模型回答不准确 | 误导学员 | 规则结果作为评分依据；回答引用知识条目；提供预设提示降级 |
| 项目范围过大 | 无法按期完成 | 第一版只支持 MySQL 和单一故事场景，其他能力后续扩展 |
| 教学沙箱被破坏 | 无法继续演示 | 使用隔离数据库、快照和一键重置脚本 |
| 危险 SQL 被执行 | 数据丢失或环境异常 | 只读账号、SQL 白名单、固定处置接口和审计日志 |
| 攻击回放被误用 | 影响非教学目标或产生破坏性行为 | 固定场景编号、禁止任意参数、网络隔离、资源限制和一键重置 |
| 备份恢复耗时或失败 | 演示卡顿 | 使用教学规模数据和独立恢复库，预置可用备份样本 |
| 环境搭建复杂 | 演示准备时间长 | 提供统一启动配置、环境检查和详细说明 |
